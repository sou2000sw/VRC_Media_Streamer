# タスク25 アプリ単位の音声取り込み — 実機テスト手順

対象ブランチ: `feature/task25-app-audio-capture`

Discord の「アプリケーション音声キャプチャ」と同じことをする機能。
**選んだウィンドウのプロセスが鳴らしている音だけ**を配信に乗せる。

---

## ★ 最初に読む: もう確認できていること / まだ分からないこと

同じことを二度測らないために、先にここを読むこと。

### ホストPC上では実測で確認済み（2026-09-06）

| 内容 | 結果 |
|---|---|
| プロセスループバックで対象の音が取れる | ffplay の 440Hz を **440.0Hz** で復元 |
| **他アプリの音が混ざらない** | 同時刻に鳴っていた440Hzが無関係プロセス側へ漏れず（rms 0.5 = ±1LSB相当）|
| 無音区間でも時間軸がずれない | 完全無音のプロセス30秒で **30.000s ちょうど**、誤差0 |
| ドリフトが蓄積しない | 20秒間 drift −3〜−4ms で増加せず、無音ガードは一度も発火せず |
| 補助exe → FFmpeg の `pipe:0` 直結 | 440Hz を 5.000s 復元。パイプ経路は成立 |
| Web UI / API | 設定の保存・読み戻し・クランプ・ウィンドウ一覧の取得まで動作確認済み |

### この手順書で確かめたいのは、まだ未確認の以下

1. **VRChatワールド内で実際に聞こえるか**（ホストPCから先は未確認）
2. **映像と音が合っているか**（画面共有と同時に使ったときのリップシンク）
3. **実アプリで取りこぼしが無いか**（ブラウザ・Discord・ゲームなど、マルチプロセス構成）
4. **長時間（30分以上）での同期ずれ**
5. **対象アプリを閉じた/音声デバイスを切り替えたときの挙動**

---

## 0. 前提

### 補助exeをビルドしておく

```bat
native\app_audio_capture\build.bat
```

`build\app_audio_capture.exe` ができれば準備完了。
ソースから起動する場合はこれで自動的に見つかる。

**Web UI に「⚠️ 補助プログラムが見つかりません」と出ていたら、ビルドできていない。**
その状態でも配信は止まらず、従来のPC出力音声／マイクだけで動く（fail-soft）。

### 動作要件

- Windows 10 build 20348 以上（この機能に必要なAPIの要件。開発機は Windows 11 26200）
- ビルドには MSVC x64 と Windows SDK（`audioclientactivationparams.h` を含むもの）

---

## 1. まずホスト側だけで確認する（VRChat不要・5分）

**VRChatを立ち上げる前にここを通しておくと、切り分けが楽になる。**

1. `Start_LocalTest.bat` で起動
2. ブラウザで `http://127.0.0.1:8000/` を開く
3. 左メニュー **「配信・QR設定」** →「ライブ音声取り込み（このPCからのみ）」
4. **「アプリ単位の音声（選んだウィンドウの音だけ）」** にチェック
5. ドロップダウンから対象ウィンドウを選ぶ（見えない場合は「デバイス再スキャン」）
6. 上部のモード選択で **「ライブ音声」** を選ぶ
7. 対象アプリで音楽などを鳴らす
8. VRChatプレイヤーURL（`http://localhost:8000/stream.m3u8`）を VLC などで開く

**期待する結果:** 対象アプリの音だけが聞こえ、他アプリの音（通知音など）は聞こえない。

> 音声のみのライブ配信は HLS だと 9〜12秒遅れる。遅延が気になるのは仕様。
> 会話用途なら配信先を TopazChat にすること。

---

## 2. VRChat内で聞こえるか

1. 上記の状態のまま VRChat を起動し、ワールドのプレイヤーにURLを入れる
2. 対象アプリで音を鳴らす

**確認すること:**

- [ ] 音が聞こえる
- [ ] 対象アプリ以外の音（Windowsの通知音、別のブラウザタブ）が混ざっていない
- [ ] 音が途切れない

---

## 3. 分離の確認（この機能の本体）

**これが確認できなければ、この機能を入れた意味が無い。**

1. アプリ音声の対象を **ブラウザ** にする
2. ブラウザで音楽を再生する
3. **同時に、別のアプリ（メディアプレイヤー等）でも別の音を鳴らす**

**期待する結果:** ブラウザの音だけが配信に乗り、もう一方は乗らない。

---

## 4. 画面共有と組み合わせる（リップシンク）

1. モードを **「画面共有」** にし、共有元を対象アプリのウィンドウにする
2. アプリ音声の対象も同じウィンドウにする
3. 人が喋っている動画を再生する

**確認すること:**

- [ ] 口の動きと音が合っている
- [ ] 30分放置しても、ずれが増えていかない

> ★タスク23の落とし穴がここにも効く。**共有元ウィンドウが他のウィンドウに覆われると
> 描画が間引かれて映像が止まる**（実測 1.4fps vs 29.6fps）。音は出続けるので
> 「音だけ進む」ように見えるが、これは映像側の既知の仕様。
> VRChatは共有元と別のモニタに置くこと。

## 5. 異常系（ここが実装の勘所）

### 5-1. 対象アプリを閉じる

配信中に対象アプリを終了させる。

**期待する結果: 配信は止まらない。** 音は無音になるが、映像も接続も生きたまま。

> 補助exeは対象が消えてもEOFを出さず無音を流し続ける設計。
> EOFにすると下流のFFmpegが入力終了と判断して**配信ごと止まる**ため。

### 5-2. 対象ウィンドウが無い状態で配信を始める

対象アプリを閉じたまま配信を開始する。

**期待する結果:** ログに `対象ウィンドウが見つからない` が出て、
**従来のPC出力音声／マイクだけで配信が始まる**（エラーで止まらない）。

### 5-3. 既定の音声出力デバイスを切り替える

配信中に Windows の出力デバイス（スピーカー↔ヘッドホン等）を切り替える。

**期待する結果:** 数秒の無音のあと復帰する。ログに再アクティベートの行が出る。

**★ここは開発機で未測定。** うまくいかない場合はログを添えて報告すること。

---

## 6. ログの読み方

ログは `vrc_media_streamer.log`。`[AppAudio]` で絞ると見やすい。

| ログ | 意味 |
|---|---|
| `helper started pid=... mode=include` | 補助exeが起動した |
| `対象ウィンドウが見つからない` | 対象不在。従来経路で続行している（異常ではない） |
| `helper exe not found` | ビルドしていない。従来経路で続行 |
| `Initialized audio client with 16-bit PCM format` | 正常な起動 |
| `silence guard filled N ms` | **要注意。** 音が途切れた分を埋めた。頻発するなら報告 |
| `Target process ... has exited, continuing capture with silence` | 対象が消えた。配信は継続中 |
| `Device invalidated ... attempting re-activation` | 出力デバイスが切り替わった |
| `helper stopped` | 配信終了にあわせて補助exeを回収した |

### ドリフトを自分で測りたいとき

補助exeを単体で動かすと、統計が1行ずつ出る。

```bat
native\app_audio_capture\build\app_audio_capture.exe --pid 1234 --stats 5 --wav out.wav --seconds 60
```

`drift` が時間とともに増え続けていなければ正常（開発機では −3〜−4ms で一定だった）。

## 7. うまくいかないときの切り分け

| 症状 | 見るところ |
|---|---|
| チェックを入れても音が乗らない | UIに「補助プログラムが見つかりません」が出ていないか → ビルド |
| 対象を選んでも無音のまま | そのアプリは音を別プロセスから出している可能性。手順3で他アプリと比較する |
| ストアアプリ（UWP）が取れない | ウィンドウのPIDが `ApplicationFrameHost.exe` を指すため。**既知の制限** |
| 他アプリの音が混ざる | `--mode` が `exclude` になっていないか（既定は `include`） |
| 音が途切れる | ログに `silence guard filled` が出ていないか |
| 配信自体が止まる | アプリ音声を切って再現するか確認。再現するなら別原因 |

---

## 8. 補助exeを使わずに済ませたい場合（回避策）

VB-CABLE を入れ、Windows の「設定 → システム → サウンド → 音量ミキサー」で
**対象アプリの出力先だけを `CABLE Input` に変える**。
「PC出力音声」の欄で `CABLE Output` を選べば、そのアプリの音だけが乗る。

欠点: VB-CABLE の導入が要る／その間そのアプリの音が自分のスピーカーから消える
（Voicemeeter か「このデバイスを聴く」で二重化は可能）。
