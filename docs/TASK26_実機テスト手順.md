# タスク26 ウィンドウ単位キャプチャ（WGC） — 実機テスト手順

対象ブランチ: `feature/task26-wgc-window-capture`
設計の正本: [TASK26_ウィンドウ単位キャプチャ_設計.md](TASK26_ウィンドウ単位キャプチャ_設計.md)

自動テストで確認できたところまでは設計書の「P0 の実測結果」に書いてある。
**ここに残っているのは、実機（VRChat / ヘッドセット / 実運用）でしか測れないもの**だけ。

---

## 0. 前提

```bat
native\window_capture\build.bat
```

が `[build] OK -> ...window_capture.exe` を出すこと。
出ていなければ以降は**すべて従来方式（重なりが映る）で走る**ので、テストの意味が無い。

UIの「画面共有」→ ウィンドウを選ぶ欄の注意書きが
**「手前に別のウィンドウが重なっても映りません」**（緑）になっていることを確認する。
これが黄色（「重なると映ります」）なら補助exeが見つかっていない。

---

## 1. 自動テストで**確認済み**のこと（実機で測り直さなくてよい）

| 項目 | 実測値 |
|---|---|
| 重なりが映らない | マゼンタ覆い 0.00%（対照の現行方式は 25.16%） |
| GPU合成ウィンドウが黒くならない | Discord(Electron) `mean=36.3` |
| 静止画面でも途切れない | 4秒×10fps で **40フレームちょうど** |
| 本番経路 (pipe→ffmpeg→h264) | 2560x1440@30 で **300/300 フレーム、実効30.0fps** |
| 現行方式との比較 | WGC **30.0fps / CPU48%** vs 現行 **26.9fps / CPU57%**（同一ウィンドウ・同一10秒） |
| 送出解像度への整形 | 1280x1392 → **1920x1080** レターボックス、180/180フレーム |
| ハンドシェイク | 起動→ready **0.23秒** |

## 2. 実機で測ること

### 2-1. VRChat で普通に見えるか（基本）

| 操作 | 期待 |
|---|---|
| ウィンドウを選んで配信開始 | ワールドの画面にそのウィンドウが映る |
| 数分放置 | カクつき・停止が無い。HLSセグメントが3.0秒で揃う |
| 文字が読めるか | 1920x1080送出。潰れるなら送出解像度かビットレートの問題 |

### 2-2. ★重なりが映らないこと（この機能の全目的）

| 操作 | 期待 |
|---|---|
| 配信中に、対象ウィンドウの上へ別のウィンドウ（メモ帳など）を重ねる | **ワールド側の映像は一切変わらない** |
| 対象ウィンドウを背面に送る（他のアプリをクリック） | 同上。映り込みなし |
| 通知トーストが対象の上に出る | 映らない |

★ここが一つでも崩れたら**プライバシー事故**。他が全部良くてもリリースしない。

### 2-3. 黄色い枠（`--no-border`）

| 操作 | 期待 |
|---|---|
| 配信開始時に対象ウィンドウの縁を見る | **黄色い枠が出ない** |

出る場合はログに `borderless access was not granted` か
`IsBorderRequired is unavailable` が残っているはず。**枠が出ても機能自体は成立する**ので、
出た場合は「出た」と記録して先へ進む（致命ではない）。

### 2-4. 覆われたときの描画抑制（設計書 §5.5・**未測定**）

**これが実機テストの主目的のひとつ。** 推測で書かないと決めた項目。

現行UIの注意書きは「覆われると**アプリ側が描画を止めることがあり**、絵の更新が
止まって見えます」に留めてある。WGCで改善するか否かは測っていない
（自動テストでは静的なウィンドウしか試せず、有意な差が出なかった）。

| 操作 | 記録すること |
|---|---|
| 動きのあるウィンドウ（動画再生中のブラウザ等）を配信 | ログの `[wincap] stats ... dup=` を控える |
| その上に別ウィンドウを重ねて30秒 | `dup` の増え方。**増えなければ改善、増えれば従来どおり** |
| VRChatを同じモニタにフルスクリーンで置く | 同上 |

`dup` は「新しい絵が来ないので直前を送り直した回数」。
**送出fpsは常に指定どおりなので、配信が切れることは無い。** 絵が更新されるかだけの話。

→ 結果に応じて `ui/index.html` の注意書きと本ドキュメントを更新すること。

### 2-5. ウィンドウの状態変化

| 操作 | 期待 |
|---|---|
| 配信中にウィンドウをリサイズ | 落ちない。中央寄せで切り貼りされる（拡大縮小はしない仕様）。ログの `resize=` が増える |
| 配信中にウィンドウを最小化 | 絵は止まるが**配信は生きたまま**。復帰したら戻る |
| 配信中にウィンドウを閉じる | 補助exeが終了コード4で畳み、既存の「対象消失 → 待機画面」へ移る |
| 別モニタへ移動 | 映り続ける（WGCはモニタに紐付かない。現行方式との大きな差） |

### 2-6. ★タスク25（アプリ音声）との同時使用

**ここは設計上いちばん壊れやすい。** 映像は名前付きパイプ、音声は ffmpeg の stdin と、
**別々の経路を同時に使う**。自動テストでは映像側しか通していない。

| 操作 | 期待 |
|---|---|
| アプリ音声を有効にしたうえでウィンドウ配信 | 映像と音の両方が出る。音ズレが無い |
| 数分放置 | どちらも途切れない |

出ない場合、ログに `[WinCap]` と `[AppAudio]` の両方が出ているかをまず見る。

### 2-7. フォールバックと設定

| 操作 | 期待 |
|---|---|
| 設定を `desktop_crop` にして配信 | 従来動作。UIの注意書きが**黄色（重なりが映る）**へ変わる |
| `window_capture.exe` を退避して配信（`auto`） | ログに `WGC 不可 -> 合成デスクトップの切り出しへ退避` が出て、配信は続く |
| 設定を `wgc` 固定にして exe を退避 | 配信を開始せず、エラー表示になる |

### 2-8. ★補助exeが残らないこと

タスク25で**実際に2回**、補助exeだけが残った事故がある。

| 操作 | 期待 |
|---|---|
| 配信を停止 | タスクマネージャから `window_capture.exe` が消える |
| 別モードへ切り替え | 同上 |
| **本体をタスクマネージャから強制終了** | `window_capture.exe` が数秒以内に自分で消える（`--parent-pid` の見張り） |
